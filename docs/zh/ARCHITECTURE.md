# IronChat 安全架构与威胁模型技术白皮书

本文档系统性阐述 IronChat 的技术架构、加密原语设计以及安全威胁防御模型。

---

## 1. 系统全景拓扑与零知识架构

```
[ 客户端 A (手机 PWA / 浏览器) ]           [ 客户端 B (手机 PWA / 浏览器) ]
      │                                                ▲
      │ (1) AES-256-GCM 本地硬件芯片级加密            │ (5) AES-256-GCM 本地解密
      ▼                                                │
[ Cloudflare Tunnel / 宿主反向代理 (TLS 1.3) ] ────────┘
      │
      │ 仅流通乱码密文与随机 IV
      ▼
[ IronChat FastAPI 后端服务 ]
      │
      ├── SQLite WAL 存储层 (零知识密文存储)
      ├── BurnEngine 阅后即焚引擎 (秒级倒计时与 7 天滚动留存物理淘汰)
      ├── DeadManDaemon (48 小时全局无交互死人开关)
      └── Shredder 物理粉碎引擎 (随机字节多遍覆写 + 截断删除)
```

### 核心密码学原语
- **对称加密算法**：WebCrypto 原生 `AES-256-GCM`，每条消息与每个二进制附件独立生成 96 位 (12 字节) 强随机 IV (`window.crypto.getRandomValues`)。
- **密钥派生算法**：PBKDF2 + HMAC-SHA256，100,000 次高强度迭代计算，结合动态独立盐值。
- **会话鉴权**：HMAC-SHA256 防篡改签名，内置 24 小时绝对空闲过期。
- **动态身份验证**：RFC 6238 标准 TOTP，密码采用【用户名@动态码】动态绑定格式。

## 2. 四大威胁模型与防御工程

### 威胁一：网络监听与中间人嗅探
- **攻击场景**：公共 Wi-Fi、运营商 ISP、国家级网络监听或边缘 CDN 节点被旁路。
- **防御机制**：双重防线。外层为权威 TLS 1.3 传输加密，内层消息体在离开浏览器网卡前就已通过 AES-256-GCM 封装为密文。中继节点即使嗅探抓包，看到的也仅是无法解密的随机字节块。

### 威胁二：服务器被攻破或数据库泄漏
- **攻击场景**：宿主机被黑客获取 Root 权限，或数据库文件被全盘拖库。
- **防御机制**：**零知识原则 (Zero-Knowledge)**。
  - 服务端绝不存储任何用户的加密私钥或口令明文；
  - SQLite 数据库与磁盘附件目录中仅存有不可逆密文；
  - 黑客即使拷贝走整个数据库与附件，在没有客户端本地密钥的情况下，计算破解一条消息需耗费数十亿年宇宙时间。

### 威胁三：手机或电脑被物理获取与磁盘取证扫描
- **攻击场景**：手机被他人解锁翻看，或被数据恢复软件进行底层磁盘镜像扫描。
- **防御机制**：**客户端零磁盘持久化缓存 (Zero-Disk Footprint)**。
  - 解密后的明文消息与图片仅暂存在浏览器 **JavaScript 内存变量** 中；
  - `localStorage`、`sessionStorage`、`IndexedDB`、WebSQL **从不写入任何一条明文或离线密文**；
  - 关闭浏览器标签页或划掉 PWA，解密后的聊天记录即刻从物理内存中蒸发，反取证软件扫描手机磁盘一无所获！

### 威胁四：删除后的磁盘扇区数据恢复
- **攻击场景**：使用底层硬盘数据恢复工具还原被删除的数据库或附件。
- **防御机制**：**物理数据粉碎引擎 (`shredder.py`)**。
  - 当消息焚毁、撤回或过期时，系统绝不仅调用操作系统的 `unlink`；
  - 而是使用 `os.urandom()` 分块向文件物理扇区连续覆写两遍随机字节，执行 `os.fsync()` 强制刷盘，再将文件截断为 0 字节后删除，彻底粉碎底层磁介质痕迹。

## 3. 三大主动自毁机制

1. **7 天滚动留存物理淘汰 (7-Day Rolling Retention)**：
   即使标记为永久保存的消息，服务端最长物理留存期也被严格锁定为 7 天。超期自动物理粉碎，确保客户端每次打开时拉取包体积永不超过 200KB，服务器磁盘永不膨胀。
2. **48 小时死人开关 (48-Hour Dead Man's Switch)**：
   系统实时记录全局交互时间。一旦双方因不可抗力或失联连续 48 小时无任何交互，后台守护协程判定系统已被遗弃，立即触发全量物理粉碎并重置容器！
3. **一键紧急自毁 (🚨 删库跑路)**：
   任何一方均可在界面点击触发。向所有客户端广播断开后，全量物理粉碎所有数据库、附件与 TOTP 秘钥，并在 1 秒内重启容器，彻底恢复出厂初始态。
